# AI 能替你做渗透测试吗？我做了个开源 AI 渗透 Agent，聊聊真实体验和取舍

> 备用标题：
> 1. 从「抓包工具 + AI 插件」到「Agent 原生」：一个全栈一体化渗透测试工具的设计笔记
> 2. 让 AI 自己测网站,人在环里做判断——开源项目 Hemlock 的开发复盘

## 开头

先说结论：**目前 AI 还替不了你做渗透测试,但可以替你完成渗透测试里 80% 的"脏活累活",并且把每一步都留下证据给你复核。**

我做了一个开源项目 Hemlock,一个把 AI 自主渗透 Agent 和传统抓包工具整合的 Windows 桌面应用。这篇文章不写广告词,聊聊我实际怎么设计的、踩了什么坑、以及它真实的能力边界。

## 一、为什么是"Agent 原生",而不是"抓包工具 + AI"

市面上的组合大多是：抓包软件管流量,AI 在旁边给建议。这个模式的问题在于——**渗透测试的流程是割裂的**。侦察、测试、验证、报告分散在几个工具里,靠人当胶水。

我的选择是反过来设计:让 Agent 成为工具的核心,抓包、重放、爆破、漏洞管理都作为它的能力存在。于是整个工具变成:

> **Agent 自动渗透 + 人工验证闭环。**

## 二、它真实跑起来是什么样

我拿一个授权目标演示给你看（以下是真实行为序列,非编造）：

**Step 1 — 摸清攻击面**

```
load_tools("discovery")          # 按需加载发现工具组
analyze_js(url)                  # 抓 JS 提取接口 → 从 5 个 JS 文件提取 12 个接口
fuzz_paths(url)                  # 路径爆破 → 命中 /admin、/backup.zip
http_probe(url)                  # 指纹识别 → nginx 1.18.0 + PHP 7.4
```

## 三、我做的几个关键取舍

### 1. 为什么不做 RAG

这是我觉得最值得聊的一个决定。很多 AI 工具上来就上向量检索(RAG),但我没有。原因很直接:**agentic search 比 RAG 更好用**——Claude Code 已经验证过这条路:与其提前把所有语料嵌入向量库做相似度召回,不如让 Agent 自己按需搜索,效果更好、实现更简单、也没有数据陈旧的问题。

所以我的记忆、技能、工具全部走「索引 + 按需加载」:只注入名称和摘要,需要完整内容时 Agent 自己调工具去取。

### 2. 上下文管理:不只是省钱,是不断链

渗透任务动辄几十上百次工具调用,上下文很容易爆炸。做了三层:

- **稳定前缀缓存**：system prompt 完全静态化,DeepSeek/OpenAI 的自动前缀缓存会话内只付一次
- **工具结果蒸馏**：大输出(HTTP 响应可能几 MB)按需截断 + 摘要压缩,关键引用(flow_id)保留
- **渐进式压缩**：Session Memory 免费摘要 → LLM 生成进展摘要 → 确定性压缩兜底,熔断自动回退

另外任务支持**断点续跑**——跑到一半崩了,重跑从断点继续,不用从头来。这对长任务几乎是刚需。

### 3. 情报工具,我刻意限制它的使用频率

给 Agent 加联网查 CVE 的能力很容易,难的是别让它滥用。我把情报工具放进"按需组"——**Agent 得先明确加载才能用**,系统提示词里写明"先推理,确认组件版本后再查证"。原因很简单:AI 如果每步都去联网搜索,它会变懒、变贵,而且没有自己思考。情报是验证假设用的,不是替代思考用的。

### 4. 代理策略:不是所有流量都走代理

这是个容易踩坑的点。我做了个区分:

- **攻击流量**（send_request 等）:永远直连目标,不进任何代理——保证攻击请求不被代理干扰、不泄漏给代理
- **情报流量**（查 CVE、搜索）:默认直连,直连失败(比如被墙)才自动借用用户配置的上游代理重试一次

能直连的用户零配置,被墙的用户配一次即可。

## 四、真实的能力边界(不吹)

- **通用漏洞**(SQLi/XSS/SSRF/越权等):覆盖得不错,七种验证方法 + 三态语义判定过滤误报
- **业务逻辑漏洞**:靠 Agent 推理,复杂场景仍需要人
- **WAF 识别与绕过**:只有技能库支撑,自动化闭环在做
- **N-day 自动化验证**:查 CVE 这步通了,"自动验证可打"那步(Nuclei 集成)在计划中
- **情报源**:NVD + cve.circl.lu,免费但有限速,依赖其可用性

## 五、如果你也想做一个 AI 安全工具

几点经验:

1. **先定架构哲学**——是"工具 + AI 建议"还是"Agent 原生",这决定后面所有设计
2. **上下文管理是地基**,不是优化项,长任务跑不通一切白搭
3. **人在环不是口号**——敏感操作确认、授权范围校验、证据可复核,这些让工具可被信任
4. **AI 的能力边界要说清楚**——用户预期管理比功能本身更重要
