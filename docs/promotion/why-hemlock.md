# 琳琅满目的渗透测试 Agent，为什么我选择 Hemlock？

> 一个 AI Agent 自主渗透 + 抓包闭环的开源安全测试工具（MIT · Windows x64）
> 说一句「帮我测试 https://xxx.com」，Agent 自己跑完 侦察 → 测试 → 验证 → 报告，关键步骤你在环里做判断
> 仓库：https://github.com/IHateTheWorld-LYK/Hemlock

---

## 先看一个现象：大家都在做"更强"，很少有人做"更好管"

这两年安全 Agent 工具像雨后春笋。打开 GitHub、公众号、技术社区，能看到一类工具的共同画风：

- 功能列表越拉越长，宣称的「能力」一个比一个硬核
- 大模型越换越新，参数越堆越大
- 但用起来，几个小时后你会发现：**它很强，但它失控**

强和失控并不矛盾。恰恰是因为强，才更容易失控。这个行业里，做"能力"的很多，做"管理能力的能力"的很少。

这篇不写广告词，我想认真聊聊：一个安全 Agent 工具，除了"能不能打"，还有一个经常被忽略的问题——**它能不能被驾驭**。这也是我在一堆同类里最终选了 Hemlock 的原因。

## 一、其他 Agent 是怎么做的：堆能力，然后呢？

### 功能多不多？多。能力强不强？强。然后呢？

先说公道话：现在的安全 Agent，单论能力都不差。主流工具基本都接了主流大模型，都能做到：

- 识别攻击面，跑侦察
- 发起请求，做测试
- 基于规则验证漏洞
- 汇总出报告

在"能测"这件事上，大家已经把门槛拉到不低了。真正拉开差距的，是**长跑之后**的表现。

### 长跑之后，问题开始出现

一个渗透任务往往不是三五步就结束的，而是几十上百步工具调用。跑得越久，问题越明显：

**上下文失控。** 前面聊得清楚、后面开始犯迷糊。工具调用结果越堆越多，Agent 要么忘记早期发现，要么被无关细节淹没。很多工具的做法是"加钱开大窗口"——窗口是开大了，但记忆不是上下文堆得越多越好，塞满了反而更乱。

**行为失控。** 功能越多，意味着每个功能的边界越模糊。一个宣称"能调用几十个工具"的 Agent，你怎么知道它不会在某一步自作主张发出一个你不想让它发的请求？功能多，控制就难。很多工具把控制权完全交给了模型，人只能在旁边看着。

**成本失控。** 每次请求都把几十个工具定义、整段历史全部塞进上下文。功能越多的工具，这个越严重。你得到的能力，和你为无效信息付的费，往往不成正比。

**中断即归零。** 任务跑到一半崩溃、断网、误关窗口——从头再来。在动辄跑很久的渗透任务里，这几乎是灾难。

一句话总结很多同类工具的状态：**能力很强，但不一定好用，也不一定可控。**

## 二、Hemlock 是怎么做的：能力要有，管理更要有

Hemlock 不是不做能力。43 个内置工具覆盖侦察 / 测试 / 验证 / 报告全流程，`fuzz_paths`、`analyze_js`、`cve_lookup`、`run_intruder`……该有的都有。

但 Hemlock 更想解决那个被忽视的问题：**怎么把"强"变成"可控的强"。** 下面这几条，是它真正让我决定留下的地方。

### 1. Agent 的执行是"管理"出来的，不是"堆"出来的

Hemlock 的 Agent 不是把所有工具一次性塞给模型，而是**工具按需加载**：

- 30 个核心工具（HTTP 主循环）常驻
- 发现 / 文件类工具（含联网情报）通过 `load_tools` 按需启用

用户说一句话，不会把全部工具定义灌进上下文。模型的可选项保持精干，决策负担小，也不容易在无关工具上打转。**功能多，但一次只用该用的**——这听起来简单，做起来需要克制。

### 2. 上下文是"管"出来的，不是"塞"出来的

渗透任务动辄几十上百步工具调用，上下文管理是硬骨头。Hemlock 的做法是一整套设计：

- **缓存友好的 system 拆分**：system 拆成「稳定段 + 动态段」两条消息。稳定段（角色设定 + 渗透策略）逐字节不变，动态段（技能索引、MCP 列表、长期记忆）随库变化。稳定段放在最前面且永不改变，缓存按前缀命中，动态内容怎么增删都不影响它。
- **确定性排序**：技能 / 记忆索引按名称排序，集合没变时注入文本逐字节一致——「没变就是没变」，缓存不会因为排列变了而失效。
- **记忆放对位置**：长期记忆放在 system 里（自动压缩永远不会动它），又在缓存断点之外（技能 / 记忆增删不影响前缀）。
- **渐进式压缩**：会话摘要免费层 → LLM 驱动的 AutoCompact → 确定性压缩兜底，熔断自动回退。
- **checkpoint 断点续跑**：任务每 3 步自动保存快照，崩溃 / 中断后从断点继续。

这些不是炫技。它们的共同目标只有一个：**让一个长流程 Agent 跑得久、记得住、不迷路。** 能力的上限由模型决定，能力的下限由上下文管理决定——而多数工具，恰恰在下限这里翻车。

### 3. 多 Agent 协作：不是多开聊天框，是分工管理

Hemlock 内置 5 个角色：侦察员 / 攻击手 / 验证员 / 情报员 / 报告员，共享渗透测试上下文，Coordinator 编排全流程。

关键是子 Agent 的设计：

- **分工执行、结果回写**：每个子任务有独立执行轨迹，发现回写共享上下文，主 Agent 拿到执行摘要，不是"另开一个聊天窗口"
- **角色可选**：不指定角色时按通用执行单元运行，任务目标优先，角色只是专业背景参考——避免"岗位说明书"式的角色 prompt 把能力框死
- **对话模式也能分工**：主 Agent 直接 `spawn_subagent`，不用切到专门的编排页

一个人干不过来的活，交给一支有分工的小队；这支小队还归你管。

### 4. 人在环，不是口号，是代码里的边界

Hemlock 对敏感操作（DoS / 注入 / RCE / 数据删除）强制人工确认，300s 超时自动拒绝。

工具能碰什么、必须你点头才碰什么，边界写在代码里，不是靠提示词"请谨慎"。这是"管理"的最后一环：**再强的 Agent，也得先过你这一关。**

### 5. 情报能力，但刻意限制使用频率

`cve_lookup` 按组件+版本查已知 CVE，`web_search` 联网搜利用细节。识别出 nginx 1.18.0，就能查到对应 CVE 和公开利用思路。

难的不是"能联网"，是**别让它滥用**。情报工具放在按需组，Agent 得先明确 `load_tools` 才能用；系统提示词写明"先推理、确认组件版本后再查证"。AI 如果每步都去联网搜，会变懒、绕开自己的推理。**情报是验证假设用的，不是替代思考用的。** 这同样是一种管理：管住"太想表现"的 Agent。

## 三、横向对比：一张表说清楚差别

| 维度 | 常见安全 Agent | Hemlock |

| 工具能力 | 越多越好，全量塞进上下文 | 43 个工具覆盖全流程，但按需加载，一次只用该用的 |

| 长任务 | 中断即归零 | checkpoint 断点续跑 |

| 一句话 | **能力很强，但不一定可控** | **有能力，还管得住** |

## 四、它到底是不是一个"优秀的 Agent"

回到开头的问题。什么是一个优秀的 Agent？

我认为不止是"任务完成度高"，还要看：**它是不是一个你愿意让它独立跑很久、并且全程不放心的对象。**

Hemlock 在"能力"上没有掉队——该有的工具、情报、协作都有；在"管理"上做了一套完整的工程实现——上下文、记忆、压缩、续跑、人在环、按需加载。这套东西的价值在于：**它不是把能力堆在一起，而是把能力组织成一个你可以信任的流程。**

所以我的结论是：

> Hemlock 不仅是一个安全测试 Agent，更是一个**懂得管理自己的 Agent**。在大家拼"更强"的时候，它选择拼"更好用、更好管"——而后者，才是长跑里真正决定体验的东西。

## 五、实用性：说这么多，用起来怎么样

- **三分钟上手**：下载安装包（Windows x64）→ 填一个 LLM API Key → 说「帮我测试 https://xxx.com」，Agent 自己跑
- **流程不割裂**：抓包代理（mitmproxy 11）、Repeater、Intruder、漏洞管理都在一个桌面应用里，Agent 测出来的请求能看到原始包，漏洞带原始请求/响应证据，可一键发到重放器 / 爆破器 / AI 继续深挖
- **人工验证闭环**：每个漏洞带证据 + 三态验证（真漏洞 / 疑似 / 误报）+ 7 种验证方法过滤误报，支持自动复测——Agent 说"发现 SQL 注入"，你能看到原始请求、响应、验证方法，自己复核
- **多 LLM 随便换**：OpenAI 兼容 SDK，DeepSeek / OpenAI / 通义 / Gemini / Kimi / 智谱 / Ollama / 自定义端点都能接，不绑定任何一家

## 六、能力边界（不吹）

- **通用漏洞**（SQLi / XSS / SSRF / 越权等）：覆盖得不错，七种验证方法 + 三态语义判定过滤误报
- **业务逻辑漏洞**：靠 Agent 推理，复杂场景仍需要人深挖
- **WAF 识别与绕过**：有技能库支撑，自动化闭环仍在完善
- **N-day 自动化验证**：「查 CVE」这步已通，「自动验证可打」在计划中

## 总结

安全 Agent 工具不缺"强"，缺"可控的强"。

大多数工具在拼功能数量、拼模型能力，Hemlock 选择把这些能力组织成一整套可管理的流程——工具按需加载、上下文拆分管理、记忆永不丢失、长任务断点续跑、敏感操作人在环、情报使用被刻意约束。

**在功能多不多、能力强不强之外，它更在意另一件事：这个 Agent，能不能被信任地驾驭。** 这也是为什么在一众渗透测试 Agent 里，我选择了它。
