# 琳琅满目的渗透测试 Agent，为什么我选择 Hemlock？

> 一个 AI Agent 自主渗透 + 抓包闭环的开源安全测试工具（MIT · Windows x64）
> 说一句「帮我测试 https://xxx.com」，Agent 自己跑完 侦察 → 测试 → 验证 → 报告，关键步骤你在环里做判断
> 仓库：https://github.com/IHateTheWorld-LYK/Hemlock

## 为什么会有这篇

这几年渗透测试相关的 AI 工具冒出来一堆：有把 AI 塞进 Burp 插件的，有做一个聊天框让它"建议"怎么测的，也有把 Agent 当作套壳聊天机器人的。

工具多了，人反而不好选。这篇不写广告词，只讲我挑工具时到底在看什么，以及 Hemlock 在哪些技术点上对上了我的标准。重点放在 Agent 本身的技术设计上，这些决定了它能跑多远、好不好用。

## 先亮个标准：Agent 工具好不好，不看"接没接 GPT"，看骨架

市面上一类做法是：抓包软件管流量，AI 在边上给建议，侦察、测试、验证、报告散落在几个界面里，靠人当胶水把流程串起来。

这不算 Agent 工具，算"带 AI 功能的测试工具"。

我判断一个 AI 渗透工具是"真 Agent"还是"套壳"，就看三件事：

1. **Agent 是不是执行主体**——流量、重放、爆破、漏洞记录，是不是都由 Agent 调用工具完成，而不是它只会"说"、人负责"做"。
2. **上下文能不能撑住长流程**——渗透任务动辄几十上百步工具调用，上下文管理是硬骨头，这一层做不好，Agent 前面聊得好好的、后段就开始犯迷糊。
3. **有没有人在环的控制权**——AI 能跑，但关键操作谁点头、证据谁复核、误报谁过滤，边界得清楚。

Hemlock 在这三点上，做的都是能落到代码里的硬设计，不是概念。

## 一、Agent 技术层面：它是怎么"自己干活"的

### 1. ReAct 编排引擎，工具即能力，按需加载

核心是 43 个内置工具，覆盖侦察 / 测试 / 验证 / 报告全阶段：`send_request`、`run_intruder`、`verify_vulnerability`、`report_finding`、`fuzz_paths`、`analyze_js`、`run_command`……

设计上两个细节值得说：

- **工具按需加载**。30 个核心工具（HTTP 主循环）常驻，发现 / 文件类工具（含联网的情报工具）通过 `load_tools` 按需启用。用户说一句话，不会一次性把所有工具定义塞满上下文——工具的"可选项"保持精干，模型决策负担小，也不容易在无关工具上打转。
- **工具结果自动化蒸馏**。超大 HTTP 输出按需截断 + 摘要压缩，但保留 `flow_id` 等关键引用，Agent 想深查随时能查。蒸馏不切断追溯，这是关键。

### 2. 上下文管理：缓存友好的 system 拆分 + 渐进式压缩 + 断点续跑

这是我认为 Hemlock 和套壳工具差距最大的一块。

**system 提示词拆成「稳定段 + 动态段」两条消息。** 稳定段（角色设定 + 渗透策略）逐字节不变，动态段（技能索引、MCP 列表、长期记忆）会随库变化。这样设计的意义在于：缓存是按前缀匹配的，稳定段放在最前面且永不改变，前缀就能稳定命中缓存；动态段内容再怎么增删，都不影响稳定段。这是把"越靠前的东西越不能动"这个原则直接落到了消息结构上。

配套还有两个约束：

- **确定性排序**。技能 / 记忆索引按名称排序，集合没变时注入文本逐字节一致——"没变就是没变"，缓存不会因为排列方式变了而失效。
- **记忆放对位置**。长期记忆放在 system 里（自动压缩永远不会动它），但又放在缓存断点之外（技能 / 记忆增删不影响前缀）。既保鲜，又不拖累缓存。

再往下是**渐进式压缩**：会话摘要免费层 → LLM 驱动的 AutoCompact → 确定性压缩兜底，熔断自动回退。长任务不爆上下文，不是靠"开大窗口"硬扛。

最后是 **checkpoint 断点续跑**：任务每 3 步自动保存快照，崩溃 / 中断后重跑同一任务自动从断点继续。对跑了几十分钟的长流程测试，这几乎是刚需。

### 3. 多 Agent 协作，不是多开几个聊天框

Hemlock 内置 5 个角色：侦察员 / 攻击手 / 验证员 / 情报员 / 报告员，共享渗透测试上下文，Coordinator 编排全流程。

这套设计有讲究：子 Agent 不是"再开一个聊天窗口"，而是**分工执行、结果回写**——各自的任务有独立执行轨迹，发现会记回共享上下文，主 Agent 能拿到子任务的执行摘要。对话模式下主 Agent 也能直接 `spawn_subagent` 分工，不用切到专门的编排页。

而且子 Agent 的角色是**可选**的——不指定角色时按通用执行单元运行，任务目标优先，角色只是专业背景参考。这样避免"岗位说明书"式的角色 prompt 把子 Agent 的能力框死。

### 4. 情报能力，但刻意限制使用频率

`cve_lookup` 按组件+版本查已知 CVE（NVD + cve.circl.lu），`web_search` 联网搜利用细节。识别出 nginx 1.18.0，就能查到对应的 CVE 和公开利用思路。

难的不是"能联网"，是**别让它滥用**。情报工具放在按需组里，Agent 得先明确 `load_tools` 才能用；系统提示词写明"先推理、确认组件版本后再查证"。AI 如果每步都去联网搜，会变懒、会绕开自己的推理。**情报是验证假设用的，不是替代思考用的。**

### 5. 人在环安全控制：边界写死

敏感操作（DoS / 注入 / RCE / 数据删除）强制人工确认，300s 超时自动拒绝。工具能碰什么、必须你点头才碰什么，边界在代码里是明确的，不是靠提示词"请谨慎"。

## 二、实用性：装好就能用，流程不割裂

技术做得再漂亮，用起来是另一回事。实用性上我关心这几点：

### 1. 三分钟上手

- 下载安装包双击装好（Windows x64，Tauri 打包，体积小）
- 设置页填一个 LLM API Key（DeepSeek / OpenAI / 通义 / Anthropic / Kimi / Ollama 都行）
- 建项目，说「帮我测试 https://xxx.com」

不需要先学渗透，Agent 自己侦察、自己测、自己出报告。对小白友好，对专业用户它也不挡路——全程可中断、可干预、可深查。

### 2. 抓包和 Agent 在同一个应用里闭环

这是"缝合"的价值所在：抓包代理（mitmproxy 11）、Repeater 重放、Intruder 爆破、漏洞管理都在一个桌面应用里。Agent 测出来的请求，你能在流量列表里看到原始包；漏洞管理页里每条记录都带**原始请求 / 响应证据**，可以一键发到重放器、爆破器或 AI 助手继续深挖。

不用在几个工具之间来回切，流程是连贯的。

### 3. 人工验证闭环：AI 不背锅，你说了算

每个漏洞带证据 + 三态验证（真漏洞 / 疑似 / 误报）+ 7 种验证方法过滤误报，支持自动复测确认修复状态。Agent 说"发现 SQL 注入"，你能看到原始请求、响应、验证方法——自己复核，而不是它说啥信啥。

### 4. 多 LLM 随便换

底层用 OpenAI 兼容 SDK，DeepSeek / OpenAI / 通义 / Gemini / Kimi / 智谱 / 百川 / Ollama / 自定义端点都能接。哪个便宜、哪个快，随你换，不绑定任何一家。

## 三、能力边界（不吹）

- **通用漏洞**（SQLi / XSS / SSRF / 越权等）：覆盖得不错，七种验证方法 + 三态语义判定过滤误报
- **业务逻辑漏洞**：靠 Agent 推理，复杂场景仍需要人深挖
- **WAF 识别与绕过**：有技能库支撑，自动化闭环还在完善
- **N-day 自动化验证**：「查 CVE」这步已通，「自动验证可打」在计划中

## 总结

挑渗透测试 Agent，我不看它接了几个大模型、宣传语写得多响，看的是：Agent 是不是真的在执行、上下文管理撑不撑得住长流程、人在环有没有控制权。

Hemlock 在这三件事上都给出了落到代码里的设计——缓存友好的 system 拆分、确定性索引排序、渐进式压缩、checkpoint 续跑、多 Agent 协作、人在环安全控制。加上三分钟上手、抓包到漏洞管理全闭环、证据链复核，它在"能用"和"好用"之间，站得比较稳。
