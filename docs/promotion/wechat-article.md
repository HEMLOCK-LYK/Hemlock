> 备用标题：
> 1. 渗透测试,能不能像跟 AI 聊天一样简单?
> 2. 一个能把「帮我测试」变成漏洞报告的 Windows 工具

## 先讲一个画面

假设你想知道自己的网站安不安全。传统流程是这样：

装抓包工具 → 配置代理 → 装证书 → 学会怎么看流量 → 然后……对着目标网站,不知道从哪下手。抓到的包一堆,接口找不到,漏洞原理记不全,poc 不会写。大多数人,第一周就劝退了。

如果我告诉你,这个流程可以变成一句话呢?

你在对话框里输入:

> **「帮我测试这个站点」**

然后,它自己开始干活了——

## 这不是「抓包工具 + AI 插件」

市面上也有在抓包软件里接一个 AI 面板的。但那是"工具为主,AI 在旁边建议"。

Hemlock 反过来——**以 Agent 为核心设计**。抓包、重放、爆破、漏洞管理,全部是 Agent 的能力,不是要你去学的工具。你只需要用自然语言说目标,剩下交给编排器。

这就是我们说的「全栈一体化」：

> **Agent 自动渗透 + 人工验证闭环。**
> AI 跑完侦察、测试、验证、报告；你在关键节点点头放行、复核证据、做最终判断。AI 不背锅,你说了算。

## 几个我用了之后觉得"值"的地方

**1. 小白真的能上手**
不需要先懂渗透。装好 → 配个 LLM Key → 说目标,就开始了。该有的专业功能(抓包解密、重放、爆破、漏洞管理)一个不少,等你需要的时候它们就在那。

**2. 每个结论都带证据**
AI 说"这里 SQL 注入",不是嘴上说说。原始请求、响应、验证方法都给你摊开,你可以自己确认,再决定上不上报。做安全的人都知道,「可复现」比「听起来对」重要得多。

**3. 查历史漏洞不用靠猜**
识别出 nginx 1.18.0,它直接去查这个版本有哪些 CVE、有没有公开利用、利用细节是什么。N-day 情报(组件+版本 → 已知漏洞)这条链路,是完整打通的。

**4. 长任务不会断链**
渗透测试经常一跑几十分钟。内置上下文管理让 Token 消耗可控、长任务不爆上下文;中途崩了还能断点续跑,不用从头再来。这对实际使用是刚需。

**5. 安全和边界是刻死的**
敏感操作(批量攻击、执行系统命令、跑脚本)强制人工确认,你点头才继续;所有请求都有授权范围校验。工具能碰什么、必须你同意才碰什么,边界写得很清楚。

## 诚实地说,它也有短板

- 业务逻辑漏洞这类「要靠理解业务」的,复杂场景仍需要人深挖
- WAF 识别和绕过的自动化闭环还在做
- 查到 N-day 到「自动验证可打」之间,还有一步在计划中(Nuclei 集成)

我们选择先把地基打扎实:Agent 原生架构、上下文管理、漏洞证据链,这些是长期有价值的东西。
